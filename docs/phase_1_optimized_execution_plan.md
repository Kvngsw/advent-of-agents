## 2. Analysis & Veto of Baseline Plan

### A. Strengths Identified
* **Pre-flight AST Security Gate:** Validating AST safety locally before issuing HTTP network requests saves compute resources and latency.
* **Low-Memory Streaming Architecture:** Generator-based stream processing (`media_chunker.py`) guarantees RSS RAM stays strictly below $\le 384\text{ MiB}$.

### B. Critical Bottlenecks & Weaknesses Identified
1. **Mock Execution Gap:** Developing Sprint 1 and Sprint 3 without shared Pydantic payload definitions creates isolated component development and causes Sprint 4 integration breakage.
2. **AST Obfuscation Exploits:** Standard AST check passes can be bypassed with dynamic attribute lookups (e.g. `getattr(__builtins__, "ex" + "ec")`).
3. **Stream Memory Allocations:** High-frequency base64 allocations on streaming video/audio can trigger memory ballooning and Garbage Collection spikes.

### C. Plan Vetoes & Key Optimizations Applied
* **VETO #1 (Loose Payload Contracts):** Vetoed loose dictionary passing across component boundaries. Introduced `src/governance/schemas.py` in Sprint 1 to establish strict Pydantic structures for `ExecutionRequest`, `ExecutionResult`, and `TelemetryFrame`.
* **OPTIMIZATION #1 (HMAC Sandbox Coupling):** The Cloud Run sandbox endpoint in Sprint 2 directly verifies the HMAC capability tokens created in Sprint 1 before executing untrusted code.
* **OPTIMIZATION #2 (Zero-Copy Buffering):** Audio and video chunking in Sprint 3 uses `memoryview` and pre-allocated byte buffers to prevent GC thrashing under low-RAM limits.

## 4. Acceptance Criteria (Given / When / Then)

### 4.1 AC-1: Cloud Run Scale-to-Zero Sandbox Execution (Day 7)
- **Given** an untrusted Python script generated by an agent containing arbitrary dynamic code,
- **When** submitted to the Cloud Run Sandbox Execution endpoint `/api/v1/sandbox/execute`,
- **Then** the service must execute the script inside an isolated container with `read-only` root filesystem (except ephemeral `/tmp`), enforce memory cap at 512MiB, complete or terminate within 15 seconds, and return parsed structured outputs without exposing host environment variables or GCP credentials.

### 4.2 AC-2: AST Security Quarantine & Blacklisted Primitives (Day 7)
- **Given** agent-generated code attempting socket manipulation (`import socket`), host inspection (`os.system`, `subprocess.Popen`), or file writes outside `/tmp`,
- **When** processed by the Governance AST Analyzer prior to dispatch,
- **Then** the request must be rejected with HTTP 403 (`SECURITY_POLICY_VIOLATION`), an audit entry written to local structured logs, and zero network calls made to Cloud Run.

### 4.3 AC-3: Gemini Live Sub-300ms Bidirectional Streaming (Day 8)
- **Given** an active bidirectional streaming session connected to `gemini-2.0-flash-exp` via Gemini Live WebSockets,
- **When** 16-bit 16kHz raw PCM audio chunks and 640x480 video frames are streamed concurrently,
- **Then** the round-trip perceptual latency from end of user speech token to first inbound synthetic audio buffer frame must not exceed 300ms under standard Codespace broadband conditions.

### 4.4 AC-4: Low-RAM Infrastructure Footprint Compliance
- **Given** execution within a memory-constrained standard GitHub Codespace (2-core, 4GB RAM),
- **When** streaming multimodal payloads and holding active WebSockets for 10 consecutive minutes,
- **Then** total harness resident set size (RSS) memory must remain strictly below 384 MiB by utilizing Python streaming generators, chunked I/O, and proactive object reclamation.

## 5. Tradeoff Matrix

| Decision Area | Option Considered | Chosen | Implementation Cost | User Friction | System Complexity | Rationale |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Code Sandboxing Engine** | Local Docker-in-Docker | No | Medium (3 hrs) | High (Codespace cgroup conflicts) | High | Host Docker engine inside Codespace can exhaust memory and trigger permission errors. |
| **Code Sandboxing Engine** | Cloud Run Ephemeral Micro-VM (gVisor) | **Yes** | Medium (4 hrs) | Low (Zero local overhead) | Low | Scale-to-zero eliminates idle cost; native gVisor security boundary isolates host kernel. |
| **Streaming Protocol** | HTTP/2 Server-Sent Events (SSE) + REST | No | Low (2 hrs) | High (High latency ~800ms) | Medium | Unidirectional SSE cannot handle simultaneous low-latency full-duplex voice/telemetry. |
| **Streaming Protocol** | Native WebSockets (Gemini Live Bidi) | **Yes** | High (5 hrs) | Minimal (<300ms latency) | High | True full-duplex protocol supports real-time interruptions and concurrent audio/video delivery. |
| **AST Policy Enforcement** | Post-Execution Static Analysis | No | Low (1 hr) | High (Vulnerabilities execute) | Low | Ineffective; allows rogue operations to trigger before post-mortem cleanup. |
| **AST Policy Enforcement** | Pre-Flight Syntactic AST Interception | **Yes** | Medium (3 hrs) | Minimal (Deterministic pre-check) | Low | Prevents unsafe execution payloads from ever hitting compute resources. |

## 6. Technical Edge Cases & Bottlenecks

1. **Codespace Cold Networking & WebSocket Keep-Alive:**  
   *Failure Mode:* Cloud-hosted Codespaces may drop long-lived WebSocket sessions during packet idle times.  
   *Mitigation:* Implement client-side heartbeat ping/pong frames at 15-second intervals with automated exponential backoff reconnection.

2. **Multimodal Memory Leaks on High-Framerate Video Feeds:**  
   *Failure Mode:* High-frequency base64 string allocations for video frames cause memory ballooning in Python's garbage collector.  
   *Mitigation:* Utilize zero-copy memory views (`memoryview`) and pre-allocated bytearray buffers for audio/video frame ingestion. Force garbage collection cycles upon streaming termination.

3. **Cloud Run Cold-Start Latency Spike on Untrusted Code:**  
   *Failure Mode:* If instances scale to absolute zero, initial container provisioning can exceed 1,500ms, stalling the automation loop.  
   *Mitigation:* Implement an eager warm-up probe ping during session handshake or maintain `--min-instances 0` with client-side execution pipelining.

4. **AST Obfuscation & Dynamic Code Execution (`eval`, `__import__`):**  
   *Failure Mode:* LLM generates obscured or nested dynamic code (e.g., `getattr(__builtins__, "ex"+"ec")`).  
   *Mitigation:* Deploy comprehensive AST NodeVisitor auditing that rejects any dynamic lookup on `__builtins__`, string concatenation feeding execution builtins, and unapproved imports.
